# 실수 노트

같은 실수를 두 번 하지 않으려고 남긴다. 작업하면서 계속 덧붙인다.

## 1. "적용했습니다" 로 끝내지 않는다

**무슨 일**: 크기·정렬처럼 눈으로 판단하는 항목을 고친 뒤 코드만 보여주고 끝냈다.
사용자가 "아직도 보인다" 고 세 번 지적했다.

**왜 틀렸나**: 코드가 바뀐 것과 화면이 바뀐 것은 다른 문제다. 캐시, 상속, 선택자 우선순위가
사이에 끼어 있어서 "고쳤다" 는 주장에 근거가 없었다.

**앞으로**: 크기·간격·정렬·색은 반드시 **숫자로 재서** 전후를 같이 보여준다.
`getBoundingClientRect`, `getComputedStyle`, 필요하면 렌더된 PNG 의 픽셀을 직접 센다.

## 2. 헤드리스 가상 시간에서는 transition 이 안 흐른다

**무슨 일**: 모바일 메뉴 패널 높이를 재니 열어도 0px 이라 "버그" 라고 두 번 보고했다.
실제로는 정상이었다.

**왜 틀렸나**: `--virtual-time-budget` 은 타이머를 건너뛴다. transition 중인 속성을 읽으면
시작값이 그대로 나온다.

**앞으로**: 측정 전에 아래를 주입한다.
```js
'*,*::before,*::after{transition:none!important;animation:none!important}'
```

## 3. 한 군데만 보고 "전부 고쳤다" 고 하지 않는다

**무슨 일**: 태그 칩 크기를 카테고리 페이지에서만 확인하고 끝냈다.
메인·아카이브·글 상세는 다른 컴포넌트(`Chip.astro`)를 써서 그대로였다.

**왜 틀렸나**: 같은 "태그 칩" 이 두 가지 구현으로 존재하는 걸 확인하지 않았다.

**앞으로**: 공통 요소를 고칠 때 **쓰이는 자리를 먼저 전부 찾고**, 그 자리마다 측정한다.

## 4. 사용자가 준 단서를 먼저 쓴다

**무슨 일**: "카테고리 페이지는 괜찮고 나머지가 문제" 라는 말이 나오고 나서야
두 구현이 다르다는 걸 알았다. 그 전까지는 추측으로 값만 만졌다.

**앞으로**: "A 는 되는데 B 는 안 된다" 는 말은 **A 와 B 의 차이를 먼저 찾으라는 뜻**이다.
값을 고치기 전에 차이부터 뽑는다.

## 5. 이미지 캐시를 비우지 않고 "바꿨다" 고 하지 않는다

**무슨 일**: 프로필 사진을 다시 잘라놓고 그대로 보고했는데, `node_modules/.astro` 에
예전 최적화본이 남아 사용자 화면은 그대로였다.

**앞으로**: `src/assets` 의 이미지를 바꾸면 `rm -rf node_modules/.astro` 후 dev 재기동한다.

## 6. 애매하면 추측하지 말고 되묻는다

**무슨 일**: "정렬이 밑으로 된 것 같다" 를 두 가지로 읽을 수 있었는데 한쪽으로 단정해
얼굴을 아래로 내렸다. 원하던 건 반대(위로 올리고 상체 넣기)였다.

**앞으로**: 해석이 갈려서 결과가 정반대가 되는 경우에는 **렌더한 시안을 보여주고** 고르게 한다.

## 7. 글자 크기는 em 박스가 아니라 "잉크" 로 잰다

**무슨 일**: 칩 테두리가 글자보다 크다는 지적에, `getComputedStyle` 과 `Range` 로 재서
"글자가 상자의 75% 를 채운다" 며 문제없다고 답했다. 실제로는 1.76 배 헐렁했다.

**왜 틀렸나**: `Range.getBoundingClientRect` 는 폰트의 **em 박스**를 준다.
눈에 보이는 한글 잉크는 글자 크기의 약 0.88 배라, 14px 글자의 잉크는 12.3px 다.
본문에서는 이 차이가 안 보이지만 **테두리를 두른 작은 요소에서는 그대로 드러난다.**

**앞으로**: 테두리·배경이 있는 작은 요소는 **렌더된 PNG 의 픽셀 행을 직접 센다.**
어두운 행 = 글자 잉크, 옅은 행 = 테두리. 목표 비율은 1.4 배 안팎.

## 8. 크기는 소수점 없이 px 로 쓴다

**무슨 일**: `1.55rem`, `.875rem`, `.3rem .7rem` 처럼 소수 rem 을 섞어 써서
실제 px 이 24.8 / 14 / 4.8 로 떨어졌다. 값을 조정할 때마다 환산을 다시 해야 했다.

**앞으로**: 글자·여백 크기는 **정수 px** 로 적는다. 제목은 25 / 20 / 17,
칩은 14, 여백은 8 / 10 처럼 한눈에 읽히는 값만 쓴다. 비율(line-height)만 소수를 허용한다.

## 9. Tailwind 임의값 유틸리티는 클래스 순서로 이기지 않는다

`class:list` 에 `text-[14px]` 와 `text-[12px]` 를 같이 넣고 뒤엣것이 이길 거라 여겼다.
특이도가 같아 **CSS 출력 순서**가 이긴다. 조건부로 크기를 바꿀 때는 한 표현식에서
배타적으로 고르거나, 아예 옵션을 만들지 않는다.

## 10. 공개 페이지에 이력서 내용을 옮기지 않는다

**무슨 일**: About 의 "Who am I" 를 다시 쓰면서, 참고용으로 읽은 이력서 PDF 의
구체적인 성과(사용 기술, 저장소 스타 수, 집필 중인 책)를 그대로 옮겨 적었다.

**왜 틀렸나**: 이력서와 공개 블로그는 **독자와 목적이 다르다.** 블로그에 적힌 구체적인 성과는
면접에서 그대로 질문이 되어 돌아온다. 사용자가 "적당한 내용" 을 원한 이유가 그것이다.
게다가 옮겨도 되는지 묻지 않았다.

**앞으로**: 사용자가 보여준 자료는 **참고만 하고 결과물에 옮기지 않는다.**
옮겨야 할 것 같으면 먼저 묻는다. 공개 페이지에는 태도와 방향만 쓰고,
수치·성과·회사명은 이력서에 둔다.
