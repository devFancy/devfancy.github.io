# 테스트 트리 틀

사람이 위에서 아래로 하나씩 짚어볼 수 있게 쓴다.
페이지를 뿌리로 두고, 그 아래에 확인 항목을 단다.

## 표시 규칙

| 표시 | 뜻 |
| --- | --- |
| `[실측 OK]` | 숫자로 확인했다. 사람은 넘어가도 된다 |
| `[확인 필요]` | 측정이 실패했거나 눈으로 봐야 한다 |
| `★` | 이번에 실제로 손댄 곳. 여기부터 본다 |

측정이 실패했으면 성공한 척하지 않는다. 실패했다고 적는다.

## 틀

```
1. <페이지 이름>  http://localhost:4321<경로>
├─ 1-1  <무엇을 한다>                 → <무엇이 보여야 한다>        [실측 OK]
├─ 1-2  <무엇을 한다>                 → <무엇이 보여야 한다>
└─ 1-3  ★ <이번에 바꾼 것>            → <무엇이 보여야 한다>        [확인 필요]

2. <다음 페이지>  <경로>
├─ 2-1  ...
└─ 2-2  ...

...

N. 다크 모드  (헤더 오른쪽 해·달 아이콘)
└─ 1~N-1 반복. <다크에서 달라지는 값만 적는다>
```

### 쓸 때

- **한 줄에 한 동작.** "커서를 올린다", "클릭한다"처럼 사람이 그대로 따라 할 수 있게 쓴다
- **기대값을 숫자로 쓴다.** "회색"이 아니라 "옅은 회색 `#f0f2f3`"
- 상태가 여러 단계면 그 아래로 한 겹 더 들여쓴다 (기본 -> 호버 -> 클릭 -> 해제)
- 페이지 순서는 **사람이 실제로 돌아다니는 순서**로 둔다
- 맨 아래 다크 모드는 앞을 반복하게 하고 **달라지는 값만** 적는다

## 요약표

트리 앞이나 뒤에 붙인다. 무엇이 왜 바뀌었는지 한눈에 보이게 한다.

```
| | 전 | 후 |
| --- | --- | --- |
| <항목> | <값> | <값> |
```

코드가 정리된 것도 같이 적으면 리뷰가 쉬워진다.

```
| | 전 | 후 |
| --- | --- | --- |
| 규칙 수 | 5줄 | 3줄 |
| 같은 일을 하는 구현 | 3가지 7곳 | 클래스 1개 |
| 죽은 코드 | .fx-title-link | 제거 |
```

## 예시 (실제로 쓴 것)

```
3. 카테고리  /category/
├─ 3-1  묶음 칩(기술)
│  ├─ 커서만                       → 옅은 회색 #f0f2f3         [실측 OK]
│  ├─ 클릭                         → 진한 회색 #3b4149 흰 글씨  [실측 OK]
│  ├─ 선택된 채 커서                 → 진한 회색 유지 (호버가 못 이김) [실측 OK]
│  └─ 하위 잎 칩이 아래 줄에 나타남
├─ 3-2  태그 칩(#Spring)
│  ├─ 기본                         → 옅은 회색 바탕 (원래 그럼)
│  ├─ 커서                         → 한 단계 짙은 회색 #e3e5e6   [실측 OK]
│  └─ 다시 클릭(해제)                → 짙은 회색으로 복귀          [실측 OK]
└─ 3-3  ★ "전체" 칩 클릭            → 필터가 풀리고 전체 목록      [확인 필요]
```
