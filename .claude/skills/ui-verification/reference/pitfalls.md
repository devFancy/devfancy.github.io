# 측정이 거짓말한 사례

전부 실제로 겪은 것이다. **코드가 틀린 경우보다 측정이 틀린 경우가 많았다.**
재기 전에 읽는다.

## 1. 스크롤한 뒤 좌표를 다시 읽지 않았다

`scrollIntoView` 로 요소를 화면 가운데로 보낸 다음, **그 전에 읽어둔 좌표**로 마우스를 옮겼다.
커서가 엉뚱한 곳에 있었고 값은 기본값이 나왔다. 네 곳 중 세 곳이 "커서 안 닿음"이었다.

**어떻게 한다**: 스크롤 -> 기다림 -> **좌표 다시 읽기** -> 마우스 이동. 순서를 지킨다.
클릭 뒤에 목록이 다시 그려지는 화면에서는 클릭할 때마다 좌표를 다시 읽는다.

## 2. `:hover` 가 붙었는지 확인하지 않았다

배경색만 읽으면 커서가 안 닿아도 숫자는 나온다. 그 기본값을 호버값으로 적을 뻔했다.

**어떻게 한다**: 값을 읽을 때 `e.matches(':hover')` 를 **같이** 읽고, 안 닿았으면 표시한다.

## 3. 스크린샷 `clip` 을 뷰포트 좌표로 줬다

`getBoundingClientRect().top` 을 그대로 `clip.y` 에 넣어 빈 이미지가 나왔다.
`Page.captureScreenshot` 의 `clip` 은 **문서 좌표**다.

**어떻게 한다**: `r.top + scrollY` 를 쓰고 `captureBeyondViewport:true` 를 같이 준다.

## 4. 헤드리스 `--window-size` 는 레이아웃 뷰포트가 아니다

375px 로 찍으라고 했는데 페이지는 `innerWidth: 500` 으로 렌더됐다. 스크린샷만 375 로 잘려서
넘친 것처럼 보였다. 그 그림을 보고 모바일 레이아웃을 여러 번 고쳤다. **고치던 것이 실제 화면이 아니었다.**

**어떻게 한다**: `Emulation.setDeviceMetricsOverride` 로 폭·높이·DPR 을 명시하고,
`document.documentElement.scrollWidth === innerWidth` 로 확인한다.

## 5. 가상 시간에서는 transition 이 안 흐른다

모바일 메뉴 높이를 재니 열어도 0px 이라 "버그"라고 두 번 보고했다. 실제로는 정상이었다.

**어떻게 한다**: 측정 전에 주입한다.
`*,*::before,*::after{transition:none!important;animation:none!important}`
색 전환을 **보고 싶을 때**는 반대로 넉넉히(400ms 이상) 기다린다.

## 6. dev 서버가 낡은 코드를 물고 있었다

`astro dev` 는 데몬이다. 새로 띄운 것이 포트를 뺏기고 **옛 프로세스가 계속 응답**해서,
코드가 바뀌었는데 화면이 안 바뀌었다. 빌드는 내내 정상이었다. 두 번 버그로 보고했다.

**어떻게 한다**: `astro dev status` 로 실제 포트를 본다. 캐시를 지웠으면 프로세스도 죽이고 다시 띄운다.
측정은 `astro preview`(빌드 결과)로 한다.

## 7. 선택자가 다른 것을 같이 잡았다

`\binline\b` 로 세었더니 1,322개가 나와 "쓰이고 있다"고 판단할 뻔했다.
전부 `inline-flex` 와 `inline-block` 이었다.

**어떻게 한다**: 클래스는 **공백으로 쪼갠 토큰**으로 센다.
`class.split(/\s+/)` 로 만든 집합에서 정확히 일치하는지 본다.

## 8. 첫 번째 요소가 기본 선택 상태였다

카테고리 칩을 `querySelector('.chip')` 로 하나 잡아 재니 호버해도 색이 안 변했다.
그게 기본 선택된 "전체" 칩이라 선택 스타일이 호버를 이기고 있었다.

**어떻게 한다**: 대표 하나를 임의로 고르지 말고 **상태별로 지목**한다.
`[data-v="기술"]` 처럼 값을 박아 고르고, 선택/미선택을 나눠 잰다.

## 9. em 박스를 잉크로 착각했다

`Range.getBoundingClientRect` 로 재서 "글자가 상자의 75%를 채운다"고 답했는데
실제로는 1.76배 헐렁했다. 그건 폰트의 **em 박스**지 눈에 보이는 잉크가 아니다.
한글 잉크는 글자 크기의 약 0.88배다.

**어떻게 한다**: 테두리나 배경이 있는 작은 요소는 **렌더된 PNG 의 픽셀 행을 직접 센다.**

## 10. 한 군데만 보고 전부 고쳤다고 했다

태그 칩 크기를 카테고리 페이지에서만 확인했다. 홈·아카이브·글 상세는 다른 컴포넌트를 써서 그대로였다.

**어떻게 한다**: 공통 요소를 고칠 때 **쓰이는 자리를 먼저 전부 찾고** 자리마다 잰다.
브라우저가 `innerHTML` 로 다시 그리는 자리는 서버 렌더 결과에 안 나오니 따로 찾는다.

## 11. CSS 특이도를 세지 않았다

`button.chip:hover`(0-2-1)가 `.chip[aria-pressed='true']`(0-2-0)를 이겨서
선택된 칩이 선택 안 된 것처럼 칠해졌다. 화면을 안 봤으면 못 잡았다.

**어떻게 한다**: 새 규칙을 얹을 때 **덮으면 안 되는 상태**를 `:not(...)` 으로 빼거나,
아예 조건을 늘리지 않는 쪽으로 설계를 고친다.
