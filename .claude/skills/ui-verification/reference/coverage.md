# 무엇을 빠뜨리기 쉬운가

측정 자체는 맞았는데 **잴 대상을 빠뜨려서** 틀린 경우가 많았다.
측정 계획을 세울 때 이 다섯 가지를 훑는다.

## 1. 쓰이는 자리를 전부 찾았나

같은 것이 **두 가지 구현으로** 존재할 수 있다. 태그 칩을 카테고리 페이지에서만 확인하고
끝냈다가, 홈·아카이브·글 상세가 다른 컴포넌트를 써서 그대로인 것을 나중에 알았다.

```bash
grep -rn '<클래스명>' src/ --include='*.astro' --include='*.css'
grep -rl "from '.*<컴포넌트>.astro'" src/
```

**브라우저가 `innerHTML` 로 다시 그리는 자리는 서버 렌더 결과에 안 나온다.** 따로 찾는다.

```bash
grep -rn 'innerHTML' src/
```

## 2. 그 페이지에 갈 수 있나

페이지가 존재하는 것과 사람이 **도달할 수 있는 것**은 다르다.
`/solutions/` 는 84편을 담고 sitemap 에도 있는데, 빌드된 327개 페이지 어디에서도
그 주소를 가리키지 않아 주소를 직접 쳐야만 갈 수 있었다.

```bash
grep -rho 'href="/경로/"' dist --include='*.html' | wc -l   # 0 이면 고아 페이지
```

새 페이지를 만들면 **들어오는 링크가 최소 하나 있는지** 센다.

## 3. 상태 조합을 다 밟았나

호버만 재고 끝내면 절반이다. 상태가 있는 요소는 조합이 곱해진다.

| 축 | 값 |
| --- | --- |
| 포인터 | 기본 / 호버 / 누르는 중 / 커서 뗀 뒤 |
| 선택 | 선택 안 됨 / 선택됨 |
| 배경 | 보통 / 사진 위 |

특히 **선택된 채로 호버**를 빠뜨리기 쉽다. 선택 표시가 호버에 덮이는 버그가 거기서 나온다.

대표 하나를 임의로 고르면 안 된다. 첫 번째 요소가 **기본 선택 상태**여서
호버가 안 먹는 것처럼 보인 적이 있다. `[data-v='기술']` 처럼 값을 박아 지목한다.

## 4. 테마와 뷰포트를 다 돌았나

- 테마: 라이트 / 다크. 토큰을 재정의하는 구조면 **양쪽 다 값이 다르다**
- 뷰포트: 작은 폰(375) / 큰 폰(390) / 데스크톱. 고정 px 는 화면이 작을수록 비율이 커진다
- 터치: `:hover` 가 탭 뒤에도 남는지. 데스크톱에서는 안 보이는 문제다

## 5. 지운 것이 정말 안 쓰이나

CSS 를 줄였으면 **지워진 규칙이 실제로 안 쓰였는지** 확인한다.
빌드 결과 전체에서 클래스 토큰을 세는 것이 가장 확실하다.

```js
const used = new Set();
for (const html of allBuiltHtml)
  for (const m of html.matchAll(/class="([^"]+)"/g))
    m[1].split(/\s+/).forEach((t) => used.add(t));
console.log(removed.map((c) => [c, used.has(c)]));
```

부분 문자열로 세면 안 된다. `inline` 을 `\binline\b` 로 셌더니 1,322개가 나왔는데
전부 `inline-flex` 와 `inline-block` 이었다.
